# 013 — Queue/Token Session Slot-on-Booking Generation

**Module:** Scheduling & Session Generation
**Status:** Ready for spec-kit intake

## User Story
As the System, I want Queue/Token Session Slots to be created one at a time, only when a booking actually happens, each carrying a never-reused token number, so that queue-based clinics get an accurate, gapless token sequence instead of a pre-filled timetable that doesn't match how walk-up queues actually work.

## Context
Queue/Token sessions serve clinics where patients are seen in arrival/booking order rather than at pre-assigned times. BDD §3.2 specifies this mode creates Slots incrementally, in contrast to Fixed-Time's pre-generation (see 012-fixed-time-slot-pregeneration).

## Business Rules
- A Queue/Token Session, once generated by the nightly job (see 011-nightly-rolling-session-generation), starts with zero Slots.
- Each booking against that Session creates exactly one new Slot at booking time.
- Every Slot created for a given Session is assigned a token number that is never reused within that Session, even if an earlier-numbered Slot's booking is later cancelled or no-showed.
- Queue-mode Sessions carry no delay figure (see 023-session-delay-tracking, which is fixed-time only); instead, queue position is derived as the count of active bookings ahead of a given Slot, plus 1 (see 024-queue-position-tracking).

## Acceptance Criteria
- Given a Queue/Token Session with zero Slots, when the first booking is made, then exactly one Slot is created with token number 1.
- Given a Queue/Token Session already has Slots with token numbers 1-5, when a new booking is made, then a new Slot is created with token number 6, regardless of whether any of tokens 1-5 were later cancelled or no-showed.
- Given a booking against token 3 is cancelled, when a subsequent booking is made on the same Session, then the newly created Slot receives the next unused token number (e.g. 6), never re-issuing token 3.
- Given a Queue/Token Session, when its current state is queried, then no delay figure is returned for it — only a queue-position figure per active booking.

## Dependencies
- Depends on: 011-nightly-rolling-session-generation — the parent Session must already exist.
- Blocks / feeds into: 018-queue-token-booking — this is the Slot-creation mechanism that booking triggers.
- Blocks / feeds into: 024-queue-position-tracking — queue position is computed over these incrementally-created Slots.

## Explicitly Out of Scope
- Fixed-time pre-generation behavior — see 012-fixed-time-slot-pregeneration.
- Delay-figure tracking for queue-mode sessions — explicitly not applicable per BDD §3.3; only queue position applies.
- Session-level live status tracking — not part of v1 (slot-level status only).
