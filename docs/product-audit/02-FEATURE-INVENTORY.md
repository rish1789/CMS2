# 02 — Feature Inventory

Labels: [RUNTIME] = observed while running · [CODE] = read in source · [INFERRED] = drawn from code or docs, not proven · [UNKNOWN] = could not be determined.

Classification: **IMPLEMENTED** · **PARTIALLY IMPLEMENTED** · **BROKEN** · **MISSING** · **UNKNOWN**. Also used: **REMOVED** (built, then deliberately taken out).

**Classification basis.** "IMPLEMENTED" means a backend path, schema, frontend and tests all exist in code, and the behaviour matches the backlog brief's main acceptance criteria as read.

**What was not executed.** Staff and patient UIs were not driven end to end; see 00 §16. Only these parts were exercised at runtime:
- startup
- public discovery
- staff and Super Admin login
- unauthenticated access to staff endpoints
- Super Admin read endpoints

**Column conventions:**
- **Tests** — counts of frontend test files (`frontend/tests/<feature>/`) and the names of the relevant backend integration and contract classes (`backend/src/test/...`). All backend *integration* classes are unexecuted here (no Docker, see 09).
- **Loading/Empty** — a grep heuristic: the component uses `LoadingState`/`ListSkeleton`/loading text, or `EmptyState`/"No … yet" text. Forms show submit states instead (not measured).
