# 014 — Schedule Edit Non-Retroactivity

**Module:** Scheduling & Session Generation
**Status:** Ready for spec-kit intake

## User Story
As a ClinicAdmin or Doctor, I want edits to a Recurring Schedule to only affect future, not-yet-generated Sessions, so that patients who already booked against an existing Session/Slot never have their appointment silently changed underneath them.

## Context
Because Sessions and Slots are materialized from Recurring Schedules by the nightly job (see 011-nightly-rolling-session-generation), a schedule edit happens against the abstract pattern, not against already-created concrete records. This feature is the explicit guarantee that the two stay decoupled once generation has occurred. BDD §3.2 confirms this is by design, not an oversight.

## Business Rules
- Editing a Recurring Schedule (time window, mode, duration, doctor assignment, etc.) never modifies any Session or Slot that has already been generated from it.
- Already-generated Sessions/Slots retain the configuration they were created with, permanently, regardless of later schedule edits.
- New Sessions generated by future nightly-job runs use the updated Recurring Schedule configuration.
- This applies uniformly to both Fixed-Time and Queue/Token schedules.

## Acceptance Criteria
- Given a Recurring Schedule that has already generated Sessions for the next 10 days, when the ClinicAdmin edits that schedule's time window, then the already-generated 10 days of Sessions/Slots are unchanged.
- Given the same edited schedule, when the next nightly job run extends the horizon, then newly generated Sessions reflect the updated time window.
- Given a Fixed-Time schedule edited to change per-patient duration, when existing pre-generated Slots are inspected, then their original duration is preserved.
- Given a Queue/Token schedule edited to change its doctor assignment, when existing Slots already booked under the old doctor are inspected, then they still reference the original doctor.

## Dependencies
- Depends on: 009-recurring-schedule-definition — this is a constraint on how edits to that entity propagate.
- Depends on: 011-nightly-rolling-session-generation — defines the generation boundary this rule protects.

## Explicitly Out of Scope
- Any retroactive "apply to existing sessions" bulk-edit tooling — deliberately not built; if a clinic needs existing sessions changed, that is a manual per-Session action outside this feature.
