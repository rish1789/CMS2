# 003 — Staff Login (Password or Staff Code)

**Module:** Identity & Access
**Status:** Ready for spec-kit intake

## User Story
As a staff member (ClinicAdmin, Doctor, or Operations), I want to log in using either my email + password or a short memorable staff code + password, so that I can access the system quickly — the staff code is especially useful on a shared front-desk device where typing a full email is friction.

## Context
BDD §3.1 notes this as "not previously documented": "Staff can log in by email+password or a short memorable staff code (e.g. `DR-4821`)." The staff code is a secondary identifier for the same Account, generated at onboarding time (004), and is unrelated to the separate, global Patient Account login system (039).

## Business Rules
- A staff Account can authenticate two ways: (a) email + password, or (b) staff code + password. Both resolve to the same underlying Account — the staff code is an alternate login identifier, not a passwordless shortcut.
- The staff code is short and memorable (e.g. `DR-4821`), generated by the system at onboarding time (see 004-staff-onboarding-direct-hire) and unique across the platform.
- Password policy applies to every staff password (initial and any later change): minimum 8 characters, requiring at least one lowercase letter, one uppercase letter, one digit, and one special character (BDD §4).
- This login system is entirely separate from Patient Account login (039) — a staff Account and a Patient Account are different identity systems even if the same real person somehow holds both.

## Acceptance Criteria
- Given a staff Account with email `dr.sharma@clinic.com` and staff code `DR-4821`, when the user logs in with the email + correct password, then they are authenticated.
- Given the same Account, when the user logs in with staff code `DR-4821` + correct password, then they are authenticated identically (same session/role).
- Given an incorrect password paired with either a valid email or valid staff code, when login is attempted, then it is rejected.
- Given a staff code that doesn't match any Account, when used to log in, then it is rejected the same way an unknown email would be (no information leak about which part was wrong).
- Given a new or changed staff password, when it doesn't satisfy the policy (8+ chars, lower, upper, digit, special), then it is rejected with a validation error.

## Dependencies
- Depends on: 004-staff-onboarding-direct-hire — staff code and initial password are generated there.
- Distinct from: 039-patient-account-global-login — separate identity system, no shared code path.

## Explicitly Out of Scope
- SSO/OAuth-based staff login (not mentioned anywhere in the source doc).
- Multi-factor authentication (not mentioned in the source doc).
- Self-service password reset mechanics beyond what's needed for initial temp-password handling in 004 — the source doc doesn't specify a reset flow, so this file only covers the two login methods and password policy; a reset/forgot-password flow should be scoped as its own decision if needed later.
